# Workbook Template

Delta spec (new capability). The downloadable XLSX template. The library used to write it is not part of this spec. Real Excel rendering cannot be verified in S1; tests read the generated bytes back through the reader port. Decisions: 4a.

## ADDED Requirements

### Requirement: Template download

`GET /api/workbook/template` MUST return HTTP 200 with the template as an XLSX file, content type `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` and a `Content-Disposition` attachment header with an `.xlsx` file name. The route MUST NOT require a body, MUST NOT call the network and MUST NOT write any file or database row.

#### Scenario: Download

- GIVEN the API is running
- WHEN a client sends `GET /api/workbook/template`
- THEN the status is 200, the content type and attachment headers are set and the body starts with the ZIP signature

#### Scenario: Deterministic content

- GIVEN two consecutive downloads
- WHEN their sheets, headers and cell values are compared
- THEN they are identical

### Requirement: Template structure

The template MUST contain the sheets `Productos`, `Variantes`, `Imagenes` and the instructions sheet `Instrucciones`. Each data sheet MUST have a first row with exactly the columns of the workbook contract, in contract order, using the contract constants as the single source. The instructions sheet MUST be written in Spanish and describe sheets, columns, required fields, accepted boolean spellings, the decimal format (`.` separator, at most 4 decimals), one barcode per variant, comma-separated tags, image `orden` rules and that `EJEMPLO-` rows must be deleted before importing.

#### Scenario: Sheets and headers

- GIVEN a generated template read through the reader port
- WHEN its sheets and header rows are listed
- THEN the four sheets exist and each data sheet header equals the contract column list

#### Scenario: Instructions are Spanish and not data

- GIVEN the generated template
- WHEN `Instrucciones` is read
- THEN it has non-empty Spanish text and the validator ignores it

### Requirement: Example products

The template MUST ship exactly two example products whose `product_key` starts with `EJEMPLO-`: one simple product (one variant, empty options) and one with options and at least two variants, each with at least one image row. Their image paths MUST pass the image path syntax check. Validating the unmodified template MUST produce zero errors and exactly one `EXAMPLE_PRODUCT` warning per example product, and no other issue.

#### Scenario: Template validates cleanly

- GIVEN the unmodified downloaded template
- WHEN it is validated by `POST /api/workbook/validate` logic
- THEN `errorCount` is 0, `valid` is true and the warnings are exactly two `EXAMPLE_PRODUCT`

#### Scenario: Example products cover both shapes

- GIVEN the template content
- WHEN its Variantes rows are grouped by product
- THEN one example has one variant with empty options and the other has two or more variants with consistent options

### Requirement: Identifier columns keep text

The `sku`, `codigo_barras` and `ubicacion` columns, and any other column intended for identifiers, MUST be written so that values typed in them are stored as text, so leading zeros are preserved. The example data MUST include a SKU or barcode with a leading zero stored as a text cell. Where the chosen writer cannot format a column as text, the instructions MUST say so and the numeric-cell rules remain the safeguard.

#### Scenario: Leading zero preserved

- GIVEN the example barcode `0123456789012`
- WHEN the template is read back
- THEN the cell kind is text and the value is `0123456789012`

#### Scenario: No numeric example identifiers

- GIVEN the template example rows
- WHEN the kind of every `sku` and `codigo_barras` cell is inspected
- THEN none is a number cell

### Requirement: Template passes its own safety checks

The generated template MUST contain no formulas, macros, external links or embedded content, and MUST pass the file-safety preflight with default caps.

#### Scenario: Preflight on the template

- GIVEN the generated template bytes
- WHEN the preflight runs
- THEN it reports no issue

### Requirement: Usability aids

The template SHOULD freeze the header row, set readable column widths and offer a true/false dropdown on `gestionar_inventario`, where the chosen writer supports them. These aids MUST NOT affect the validity of the file.

#### Scenario: Aids absent

- GIVEN a writer that cannot set a dropdown
- WHEN the template is generated
- THEN generation succeeds and validation of the template is unchanged
